# ТЗ: GeoPhotos

Итоговые решения по ответам из `tz_questions.md`. Конфигурация программы описана отдельно в `tz-config.md`.

Строки интерфейса (меню, кнопки, окна, сообщения) в этом ТЗ — по-английски, как в `locales/en.json`; русские и украинские — в файлах локализации (решение автора 2026-11-28).

## 1. Назначение

1.1. Отображение карты с маркерами или миниатюрами фотографий, у которых есть геопривязка.

1.2. Ручная привязка фотографий к карте: пользователь перетаскивает миниатюру фото на нужную точку карты. Образец интерфейса и приёмов работы — модуль Map в Lightroom.

1.3. Типичный сценарий: папка с фото из поездки, большинство в RAW без координат, среди них фото с телефона с координатами. Пользователь видит фото с телефона на карте, вспоминает место каждого снимка, находит его на карте и перетаскивает туда миниатюру. Затем сохраняет результат.

1.4. Пользователь один — автор ТЗ.

## 2. Платформа

2.1. Windows, окно на ПК. Electron + Node.js.

2.2. Внешняя зависимость — `exiftool`. Путь к нему — в настройках, по умолчанию `exiftool` из PATH. Список форматов (п. 3.3) проверен на версии 13.62, видео (п. 3.3.6) — на 13.64. При запуске программа проверяет, что exiftool доступен. Если путь из настроек не работает, программа ищет exiftool в обычных местах Windows: рядом с программой (`exiftool.exe` вместе с его папкой `exiftool_files` — без неё нынешние сборки exiftool для Windows не запускаются; из zip с exiftool.org `exiftool(-k).exe` переименовывается в `exiftool.exe`), в подпапке `exiftool` рядом с программой, в папках установщика Oliver Betz (его ставит и winget: `%LOCALAPPDATA%\Programs\ExifTool`, `Program Files\ExifTool`), winget, Chocolatey, Scoop, папка Windows; найденный используется, путь — в лог. Если не найден нигде — окно «exiftool not found» с кнопками по порядку:
- «Install for GeoPhotos» — программа узнаёт последнюю версию на exiftool.org (`ver.txt`), скачивает официальный zip для Windows (64 бита, с SourceForge, куда ведёт exiftool.org), сверяет его SHA-256 с `checksums.txt` с exiftool.org, распаковывает и кладёт `exiftool.exe` (переименованный `exiftool(-k).exe`) и папку `exiftool_files` рядом с GeoPhotos.exe, проверяет, что он запускается, и продолжает запуск. Если в папку программы писать нельзя — ставит в `%LOCALAPPDATA%\GeoPhotos\exiftool` и записывает путь в файл настроек (`exiftoolPath`). Ход — в маленьком окне (как у пакетного режима, с «Cancel»); при ошибке (нет интернета, не сошлась сумма, нет места) — сообщение, и окно выбора снова. Новые версии exiftool программа сама не ищет.
- «Install from the Website» — открывает exiftool.org в браузере; программа закрывается, после установки её запускают снова.
- «Choose exiftool.exe…» — окно выбора файла; выбранный проверяется (запускается ли), путь записывается в файл настроек, запуск продолжается; не тот файл — сообщение и окно выбора снова.
- «Close» — программа закрывается.

2.3. Язык интерфейса — английский, русский и украинский (`en`, `ru`, `uk`). Язык выбирается в меню «Tools → Language» (названия языков — на самих языках; список — по файлам локализации) или в файле настроек; выбор из меню записывается в файл настроек, и программа сразу перезапускается без вопроса: обычный выход (с вопросом о несохранённых изменениях, если они есть; «Stay» отменяет перезапуск) и запуск снова с прежней папкой (п. 7.1). Пока язык не выбран (`"auto"`, по умолчанию), берётся язык Windows (первый из языков системы, для которого есть файл локализации), иначе английский — так и первое окно (например, «exiftool not found», п. 2.2) на языке системы. Тексты интерфейса хранятся в файлах локализации, по файлу на язык; новый язык добавляется новым файлом без изменения кода. Основной язык — английский: на нём язык по умолчанию, описания полей в схеме и пояснения в файле настроек; остальные языки — дополнительная локализация интерфейса.

2.4. Способ запуска (из окружения разработки или готовый .exe) — какой проще и надёжнее.

2.5. Установка и обновление (с 0.30.0). Два вида программы, оба в каждом релизе на GitHub (п. 9.3):
- **Установщик** `GeoPhotos-Setup-X.Y.Z.exe` — мастер NSIS для текущего пользователя, без прав администратора. Страницы: приветствие; папка (по умолчанию `%LOCALAPPDATA%\Programs\GeoPhotos`, можно сменить); флажок «Create a shortcut on the desktop» (включён); установка; «Run GeoPhotos». Ярлык в меню «Пуск» — всегда. Язык мастера — английский, русский или украинский, по языку Windows. Удаление — через «Приложения» Windows; настройки и логи в `%APPDATA%\GeoPhotos` остаются (как удалить их вручную — в README). exiftool, поставленный кнопкой «Install for GeoPhotos» (п. 2.2), у установленной программы кладётся в профиль (`%LOCALAPPDATA%\GeoPhotos\exiftool`), а не в папку программы: обновление и удаление её стирают.
- **Zip** — как раньше (распаковать и запустить).

Проверка обновлений — при каждом запуске, если в настройках не выключена (`checkUpdates`, по умолчанию включена; п. 8.6): программа узнаёт последнюю версию в GitHub Releases. Без сети или при ошибке — молча, только запись в лог. Окон посреди работы нет — сообщение ненавязчивое, справа в строке состояния (п. 4.13):
- установленная программа скачивает новую версию в фоне; когда скачана — «Version X.Y.Z is ready — restart»; щелчок — выход как обычно (с вопросом о несохранённых изменениях, п. 6.5), установка и запуск новой версии. Не щёлкнули — обновление ставится само при выходе из программы. Подлинность скачанного проверяется по SHA-512 из `latest.yml` релиза (подписи кода нет, п. 9.3);
- zip-версия сама себя не обновляет: «Version X.Y.Z is available» — щелчок открывает страницу релиза в браузере.

Пункта «Открыть в GeoPhotos» в контекстном меню Проводника нет — ни в установщике, ни в программе (отказ пользователя, 2026-11-25).

2.6. Одно окно (с 0.35.0, решение автора 2026-11-25): GeoPhotos работает в одном экземпляре. Повторный запуск (ярлык, перетаскивание на значок программы или ярлык, параметры запуска, список на значке — п. 3.1) не открывает второе окно: уже открытое выходит на передний план (свёрнутое — разворачивается), а переданные папка или файлы открываются в нём так же, как при перетаскивании в окно (п. 3.1): папка — с вопросом о несохранённых изменениях (п. 6.5), файлы добавляются в ленту. Пакетный режим (п. 10) работает отдельным процессом, его это не касается.

## 3. Исходные данные

3.1. Лента собирается из папки и отдельных файлов (с 0.25.0). Всё, что сейчас в ленте, — **проект** (внутреннее название для ТЗ и кода; в интерфейсе слова нет). Термины: везде «папка» (англ. folder), не «директория»; «фото» — общее слово для фото и видео (п. 3.3.6), как в Lightroom.

Открытие папки начинает новый проект: всё, что было в ленте, заменяется всей папкой (с вопросом о несохранённых изменениях, п. 6.5, и вопросом о вложенных папках, п. 3.2). Открыть папку можно так:
- «Open Folder…» (Ctrl+O; до 0.25.0 — «Open Photo…») — окно выбора файла с фильтром по фото и видео (п. 3.3), чтобы фото в папках были видны. Выбранное фото (двойной щелчок или «Open») открывает свою папку и становится выбранным в ленте и на карте. Выбрать можно только одно фото (без Shift/Ctrl+клика): оно лишь указывает папку, открывается всегда вся папка. Только часть фото папки — через «Add Files…» (там выбор нескольких) или Del лишнего после открытия. Стандартное окно выбора папки Windows файлы не показывает, поэтому не используется. Окно открывается в текущей папке, а если папка не открыта — в последней открытой.
- «Open Recent» — последние 10 открытых папок (сверху — последняя) и «Clear Recent». С 0.35.0 те же папки — в списке на значке GeoPhotos в панели задач и в «Пуске» (правый щелчок, «Recent folders»; только в собранной программе): щелчок открывает папку в открытом окне или запускает программу (п. 2.6); «Clear Recent» очищает и его. В список попадают только папки, добавленные файлы — нет. Если папки больше нет — сообщение, папка убирается из списка.
- Перетаскивание папки из Проводника в окно программы.
- Параметр запуска — папка.

Папку без своих фото (только с вложенными, п. 3.2) открывают перетаскиванием из Проводника, параметром запуска или из «Open Recent».

Добавление файлов проект не сбрасывает: файлы добавляются в ленту к тому, что в ней уже есть, — так ленту можно собрать из разных папок. Вопроса о несохранённых изменениях нет, фильтр (п. 4.13) не сбрасывается. Добавить можно и без открытой папки. Способы:
- «Add Files…» (Ctrl+Shift+O) — то же окно выбора, с выбором нескольких файлов; открывается в папке, из которой файлы добавляли в прошлый раз (запоминается и между запусками, в файле состояния п. 7.5; в «Open Recent» не попадает), а если её нет — как «Open Folder…»;
- перетаскивание файлов (одного или нескольких) из Проводника — до 0.25.0 файл открывал свою папку;
- параметр запуска — файлы (одни файлы — проект без папки).

Если перетаскиваются (или передаются при запуске) несколько папок или папки с файлами — открывается первая папка, остальные папки не берутся, файлы добавляются к ней. Файл, который уже есть в ленте, повторно не добавляется. XMP рядом (п. 3.7) и MOV «живого» фото (п. 3.3.7) подтягиваются сами. Добавленные файлы становятся выбранными, первый из них в ленте — текущим; карта показывает добавленные с координатами (как п. 5.2, только по ним; если таких нет — не двигается).

Убрать фото или трек из ленты — Del (п. 6.6); файл на диске не меняется. Убранные файлы папки проект помнит: F5 (п. 3.8) и следующий запуск (п. 7.1) их не возвращают; вернуть — «Add Files…» или открыть папку заново.

Список последних папок хранится между запусками в файле состояния (п. 7.5).

3.2. Если в открываемой папке есть вложенные папки, программа спрашивает: «Load photos from the folders inside this one too (all levels)?» — кнопки «Yes» / «No» и флажок «Don't ask again». С флажком ответ записывается в пользовательский файл настроек (поле `folders.subfolders`: `ask` — спрашивать, по умолчанию; `yes`; `no`; комментарии файла сохраняются, `tz-config.md`, п. 5), и дальше вопрос не задаётся, пока там снова не будет `ask`. Если вложенных папок нет, вопрос не задаётся. Фото из вложенных папок идут в ленте вместе с остальными по времени съёмки; в строке состояния, подсказке миниатюры и режиме просмотра фото имя показывается с путём от открытой папки (`2024-05\IMG_0001.jpg`); у добавленного файла не из открытой папки и её вложенных (п. 3.1) — полный путь (`D:\Phone\IMG_0001.jpg`). При восстановлении прошлого сеанса (п. 7.1) берётся выбор того сеанса, без вопроса.

3.3. Форматы

3.3.1. Поддерживаются все форматы, у которых exiftool умеет читать метаданные и для которых координаты можно записать в файл или в XMP рядом. Список ниже проверен по exiftool 13.62 (`exiftool -listr`, `exiftool -listwf`). Программа работает именно с форматами из пп. 3.3.2–3.3.3; при обновлении exiftool список пересматривается вручную.

3.3.2. Обычные форматы и DNG, которые exiftool умеет записывать, — координаты пишутся в сам файл (п. 6.3) (jpg, jpeg, jpe, heic, heif, hif, avif, png, webp, tif, tiff, dng). DNG пишется внутрь, как это делает Lightroom.

3.3.3. Остальные RAW-форматы, которые читает exiftool, — координаты пишутся только в XMP рядом (п. 6.4) (cr2, cr3, crw, nef, nrw, arw, srf, sr2, arq, raf, rw2, rwl, raw, orf, ori, pef, srw, 3fr, fff, iiq, x3f, gpr, erf, mef, mos, mrw, dcr, kdc, k25).

3.3.4. Показ:
- JPEG, PNG, WebP, AVIF — как есть;
- HEIC и TIFF — Chromium их сам не показывает, для показа они преобразуются в JPEG;
- RAW (включая DNG) — встроенное в файл JPEG-превью, которое извлекает exiftool. Сам RAW не декодируется.

3.3.5. Если показать фото не удаётся (нет превью, формат не отображается), в ленте показывается значок-заглушка с именем файла. Привязка и запись работают как обычно.

3.3.6. Видео (с 0.20.0; привязка — с 0.22.0). Видео идут в ленте и на карте вместе с фото; дальше в ТЗ «фото» включает и видео, если не сказано иное. Проигрывания в программе нет. Списки проверены по exiftool 13.64 и роликам пользователя (AVI с оцифрованной кассеты, MPG Sony, MOV Canon и Olympus, MP4 телефонов Samsung и Android).
- Видео, в которые exiftool умеет писать (семейство QuickTime), — координаты, адрес и высота пишутся в сам файл (п. 6.3) (mov, qt, mp4, m4v, 3gp, 3gpp, 3g2, 3gp2, mqv, f4v).
- Остальные видео, которые читает exiftool, — только в XMP рядом (п. 6.4), сам файл не меняется (avi, divx, mpg, mpeg, m2v, vob, mts, m2ts, m2t, ts, mkv, webm, wmv, asf, flv, dv, ogv, mxf).
- Миниатюра и кадр для режима просмотра — системные, те же, что у Проводника Windows в режиме миниатюр (`nativeImage.createThumbnailFromPath`); ffmpeg не нужен. Если Windows кадр не отдаёт (нет кодека, битый файл) — заглушка (п. 3.3.5).
- Координаты читаются из метаданных QuickTime (как их пишут телефоны), XMP и EXIF; порядок — п. 3.7. Если в заголовке их нет, а в ролике есть трек (GoPro, видеорегистратор, дрон, камеры Sony), берётся первая точка трека; такой ролик читается заметно дольше — глубокое чтение только для видео, у которых других координат нет.

3.3.7. «Живые» фото (с 0.24.0): фото с коротким роликом.
- Ролик внутри файла фото: Google Motion Photo (Xiaomi, Pixel, новые Samsung; exiftool отдаёт его тегом `MotionPhotoVideo`), старые Samsung (`EmbeddedVideoFile`; с 0.27.0 — только если в XMP есть признак, п. 3.10), Pixel 2 (`EmbeddedVideo`). Проверено на Xiaomi 15 Ultra; старые форматы — только по описанию, образцов нет. Запись координат ролик внутри не портит (проверено).
- iPhone Live Photo — фото (HEIC, JPEG) и MOV с тем же именем и тем же `ContentIdentifier` в обоих файлах; совпадения имени мало. Пара — один элемент ленты (фото), MOV отдельно не показывается и в счётчике не считается. Координаты, адрес и высота пары — из фото; при записи (и при удалении координат, Ctrl+Del) — в оба файла одинаково, MOV — как видео (п. 6.3). MOV без своего фото — обычное видео (п. 3.3.6).
- В ленте — значок «живое фото» на месте значка видео (п. 4.3); при наведении мыши ролик без звука идёт по кругу поверх миниатюры, мышь ушла — снова кадр. Когда «живое» фото становится текущим (стрелкой, кликом, рамкой на карте), его ролик в ленте проигрывается один раз. В режиме просмотра (п. 4.14) ролик проигрывается один раз без звука, затем остаётся фото. На карте — без анимации. Если ролик не проигрывается (нет декодера HEVC) — обычная миниатюра, значок остаётся.

3.4. Пары RAW+JPEG с одинаковым именем — отдельные фото.

3.5. Объём: обычно 10–20 фото, бывает несколько сотен.

3.6. Часы камеры считаются точными. Коррекция времени (ручной сдвиг) не нужна. Треки (GPX и другие) — п. 3.9: с 0.26.0 показываются, с 0.28.0 помогают привязке. До 2026-11-24 от треков отказывались (сценарий казался редким); решение пересмотрено пользователем.

3.7. Откуда читаются координаты, если они есть в нескольких местах (для всех форматов одинаково): сначала XMP рядом с файлом, затем встроенный XMP, затем EXIF. Берётся первый источник, в котором координаты есть. XMP рядом (`имя.xmp`) принадлежит RAW-файлу с тем же именем, если такой есть в папке, иначе — видео с тем же именем из второго списка п. 3.3.6: у пары RAW+JPEG (п. 3.4) JPEG его не читает и при записи не меняет. Совпадение имён у RAW и такого видео не учитывается — XMP принадлежит RAW.

3.8. «File → Refresh» (F5) перечитывает проект: открытую папку — с тем же выбором вложенных папок (п. 3.2) — и добавленные файлы (п. 3.1): новые файлы папки появляются (кроме убранных из ленты), удалённые с диска исчезают, изменения, сделанные снаружи (например, другой программой), показываются. Остаются как были: текущее и выбранные фото (по пути к файлу; удалённые выпадают), фильтр (п. 4.13), место и масштаб карты, прокрутка ленты, режим просмотра. При несохранённых изменениях — сначала обычное предупреждение (п. 6.5). Автоматического отслеживания изменений нет.

3.9. Треки (с 0.26.0). Трек — файл записи пути (часы, навигатор, приложение). В 0.26.0 треки только показываются: файлы треков не меняются и не сохраняются, на координаты фото не влияют.

3.9.1. Форматы (читает сама программа, без внешних конвертеров): GPX (`.gpx`), KML (`.kml`), KMZ (`.kmz` — KML в zip), FIT (`.fit` — Garmin, Wahoo, Coros, часы), TCX (`.tcx`), GeoJSON (`.geojson`). NMEA и IGC не нужны. Из файла берутся: линии (в GPX — треки и маршруты, все отрезки; в KML — LineString и gx:Track; в FIT — записи с координатами), время точек, высота и, если есть, пульс, скорость, каденс, температура, мощность (GPX — расширения Garmin; FIT, TCX — свои поля); путевые точки с названиями (GPX `wpt`, KML Placemark с Point, GeoJSON Point); название трека и программа или устройство, записавшие его. Отрезки одного файла не соединяются. Файл без единой точки с координатами — ошибка чтения (п. 6.7), в ленте — заглушка. Проверяется на треках пользователя (часы Amazfit, навигаторы Garmin) — `C:\dev\data\geophotos\track-sample`.

3.9.2. Трек входит в проект (п. 3.1) как фото: файлы треков открытой папки (и вложенных, если выбраны, п. 3.2) загружаются вместе с фото; «Add Files…», перетаскивание и параметры запуска принимают и треки (фильтр окна выбора — «Photos, videos and tracks»); F5, восстановление при запуске и Del (п. 6.6) — как у фото. Пакетный режим (п. 10) треки пропускает.

3.9.3. Трек в ленте — один элемент на файл, по времени начала среди фото (п. 4.2); трек без времени — в конце, как фото без даты. Миниатюра — форма линии трека на тёмном фоне его цветом, со значком «трек»; строится в фоне, как миниатюры фото. Подсказка миниатюры: имя, дата начала, длительность, длина. Треки — служебные элементы: всегда видны при любом фильтре и не входят в счётчик и фильтры (п. 4.13). Строка состояния: имя, дата и время начала, длительность, длина (км), число точек.

3.9.4. Выбор трека: клик, стрелки, Home/End — как у фото. Трек выбирается один: клик, Ctrl+клик и Shift+клик по треку делают его единственным выбранным и текущим (выбранные фото снимаются); Ctrl+A выбирает только фото; рамка на карте (п. 4.4.3) треки не выбирает. Выбранный трек на карте толще и поверх остальных; если он целиком за краем карты, карта показывает его целиком. Двойной клик по треку в ленте, C и «View → Show on Map» — показать весь трек. Клик по линии трека на карте выбирает его в ленте. Трек нельзя перетащить на карту или на фото; Ctrl+C, Ctrl+V, «Save» к трекам не относятся.

3.9.5. Трек на карте — линия; цвета — по списку из настроек (`tracks.colors`, 8–10 контрастных цветов, не зелёные и не красные, чтобы не путать с маркерами фото), по порядку треков в ленте, по кругу, если треков больше. Путевые точки — флажок цвета своего трека (форма отличается от маркеров фото); название видно при наведении и при масштабе от `tracks.labelZoom` (по умолчанию 14). При наведении на линию — подсказка по ближайшей точке: время (местное время места трека, по офлайн-таблице поясов, в формате Windows), высота и то, что есть в этой точке: пульс, скорость, каденс, температура, мощность. При открытии папки карта охватывает фото с координатами и треки (п. 5.2). Треки видны в обоих режимах карты (маркеры / миниатюры, п. 4.8.3).

3.9.6. Просмотр трека — пробел (и «View → Photo View») на текущем треке; пробел ещё раз — обратно к карте. Справочный режим, не для работы: карта остаётся (она нужна, чтобы оценить трек целиком), но слегка затемнена — заметно, но не сильно — и неподвижна (не двигается и не масштабируется), вписана по треку; видны только этот трек (ярко) и его флажки, маркеры фото и другие треки скрыты. Слева сверху — сводка (только то, что есть в файле): имя, начало и конец (дата, время по месту трека), расстояние, время всего и в движении, остановки (число и общая длительность; остановка — не меньше 2 мин почти на месте), средняя скорость в движении и максимальная, набор и сброс высоты, наименьшая и наибольшая высота, пульс средний и наибольший, число точек и путевых точек, устройство или программа. Внизу — профиль высоты по расстоянию и, если есть пульс, его график под ним (только эти два — решение пользователя: скорость есть в сводке и в подсказке на линии); нет высоты — только пульс, нет ни того, ни другого — графиков нет. При наведении на график — значения, а на линии трека — точка этого места.

3.9.7. Привязка по треку (с 0.28.0). Автоматической привязки нет: трек подсказывает, а привязывает пользователь.
- Место на треке в момент съёмки: время съёмки фото переводится в мировое время по смещению пояса, записанному в снимке (телефоны пишут `OffsetTimeOriginal`), а если его нет (фотоаппараты) — по поясу места трека; между точками трека место берётся пропорционально времени. Если фото снято вне времени трека или в паузе записи (соседние точки дальше 5 минут друг от друга) — места нет. Фото без времени съёмки (дата из файла) места не имеют. Если момент попадает в несколько треков — берётся первый в ленте.
- Отметка: у текущего фото без координат, если место на треке есть, на линии трека — кольцо цвета выбранного маркера (отличается от кольца найденного места, п. 5.3). У фото с координатами отметки нет: перепривязать — сначала удалить координаты (Ctrl+Del), решает пользователь.
- Фото, брошенное на карту рядом с отметкой (24 px, как у метки места), получает точно её координаты («примагничивание»); брошенное в стороне — точку броска. Только когда тянут одно фото — текущее; несколько — каждое в точку броска.
- Фото, брошенные в ленте на трек (как на фото, п. 4.5), получают каждое своё место на этом треке по своему времени съёмки; координаты заменяются (бросок сознательный); фото без места на треке не меняются; без сообщений. Высота не трогается (п. 5.6).
- Проверено на данных пользователя: время в снимках телефона надёжно (время GPS отличается от времени съёмки на 1–5 с), а координаты телефона у части снимков ошибочны на 0,2–2 км (трек в это время там не проходил): трек помогает и исправлять их.

3.10. Скорость чтения папки (с 0.27.0). При открытии лента пуста, пока не прочитаны данные всех файлов: порядок ленты — по времени съёмки, а оно внутри файлов (п. 4.2); показ по частям не делается — миниатюры прыгали бы, а чтение и так быстрое. Чтение ускорено двумя способами (замер на 122 JPEG телефона Xiaomi: 4,1 → 0,6 с):
- exiftool не дочитывает JPEG до конца (`-fast`; на снимках телефона в 2,6 раза быстрее). Не читается только видео Motion Photo в конце файла: такое «живое» фото узнаётся по признаку в XMP в начале файла (`MotionPhoto`, `MicroVideo`), а видео достаётся при проигрывании. Следствие: старые Samsung, у которых видео только в конце файла без признака в XMP, «живыми» не определяются (образцов нет, п. 3.3.7).
- Несколько процессов exiftool: примерно один на 30 файлов открытого проекта (п. 3.1), но не больше числа настоящих ядер процессора (половина логических процессоров; больше не быстрее — замер: 8 процессов на 16 логических как 15). Файлы делятся между ними; превью RAW для миниатюр берутся из них же, миниатюры строятся параллельно по их числу (не меньше трёх). Число процессов следует за проектом, без таймеров: проект меньше — лишние закрываются; простаивающий процесс не тратит процессор, но занимает около 34 МБ памяти. 30 файлов — сколько процесс читает примерно за секунду: для меньшего числа запуск процесса (около 0,3 с) не окупается.

Кэш миниатюр на диске не нужен (решение пользователя, 2026-11-24, по замеру): миниатюра строится за 20–70 мс (RAW и DNG — встроенное превью, около 40 мс; HEIC без встроенного превью — 0,44 с), лента строит только видимые миниатюры и показывает каждую сразу, как готова, так что ожидание ограничено одним экраном (1–2 с). Вернуться к кэшу — если папки из HEIC без превью окажутся частыми.

## 4. Интерфейс

4.1. Карта на всё окно, лента миниатюр внизу или слева (с 0.33.0): «View → Strip Position» — «Bottom» / «Left» (переключатели, у текущего — точка); выбор запоминается между запусками (п. 7.1), по умолчанию — внизу. Слева — одна колонка тех же миниатюр, прокрутка вниз (колесом мыши — как обычно). Размер миниатюр ленты (с 0.37.0, решение автора 2026-11-26, по предложению Claude): граница между картой и лентой тянется мышью (курсор — двойная стрелка), лента становится выше (внизу) или шире (слева), миниатюры растут вместе с ней, карта уменьшается; то же — Ctrl+колесо над лентой и Ctrl + «+» / «−» (Ctrl+0 — обычный размер), как в сетке (п. 4.17). При смене размера текущая миниатюра остаётся на том же месте экрана, лента растёт вокруг неё (если её есть куда прокрутить; так же в сетке, п. 4.17). Пределы — от 60 пикселей (решение автора 2026-11-27; было 80) до половины окна (по высоте внизу, по ширине слева), но не больше 320 — размера самих картинок миниатюр (точные цифры автор подберёт на опыте); по умолчанию 120; запоминается между запусками отдельно от размера в сетке.

4.2. Лента упорядочена по времени съёмки. Другой сортировки на шагах 1–2 нет. Время съёмки нужно только для сортировки и показа (строка состояния, подсказка, режим просмотра); программа вычисляет его как можно правдоподобнее и никуда не пишет. Порядок:
- фото — время съёмки EXIF (местное время камеры);
- видео с явным часовым поясом (QuickTime CreationDate у iPhone, дата в XMP со смещением вида `+03:00`) — местное время по этому поясу. Дата в XMP с `Z` поясом не считается: её дописывают программы (например, Adobe) к местному времени камеры;
- видео с фотокамер (в файле есть производитель или модель камеры: Canon, Nikon, Sony, Panasonic, Olympus, Fujifilm, Pentax и т. п.; у Canon — и по `CompressorVersion`) — время QuickTime как есть: камеры пишут туда местное время, хотя по стандарту там UTC. Проверено на Canon EOS 5D Mark II (ролик и следующий кадр той же камерой), Canon (CanonAVC0001), Olympus C5060WZ;
- остальные видео (телефоны) — время QuickTime в UTC, переводится в местное время места съёмки по координатам файла (офлайн-таблица часовых поясов); без координат — в пояс компьютера. Проверено на Samsung (2019, Нью-Йорк) и Android (2025, Лима): так время совпадает с временем в имени файла. Следствие: если такому видео без координат их присвоить, после сохранения его время пересчитается по новому месту и оно может сдвинуться в ленте;
- нет даты (фото или видео) — дата и, если есть, время из имени файла (`20190816_192927`, `VID_20250426_101211`, `IMG_20190816_192927`, `1998 03 19 …`, `1998-03-19`, `1998_03_19`); только правдоподобные даты (год 1980 — текущий);
- иначе — время изменения файла. Фильтр ленты — по счётчику в строке состояния (п. 4.13), с шага 2.

4.3. Отметки в ленте: у фото есть координаты; координаты изменены, но не сохранены (значок-карандаш того же вида и размера, что значок координат; рамки нет — рамка обозначает только выделение). Значок «есть координаты» — в цветах маркеров (п. 4.8.1): обычный цвет, у выбранного фото — цвет выбранного маркера. Карандаш «изменено» (с 0.37.0, решение автора 2026-11-27) — белый, на тёмной полупрозрачной подложке, в левом нижнем углу картинки: это статус работы, а не сведения о фото, и он не теснит значки при любом размере ленты. Значки сведений — в верхней строке миниатюры, справа, каждый на своём постоянном месте (не сдвигается, если соседнего нет): координаты, адрес (п. 5.5, голубой домик), высота (п. 5.6, гора) и видео (п. 3.3.6, значок «плёнка») или «живое фото» (п. 3.3.7, жёлтые кольца). Подсказка значка — его значение, без слов «есть…» (сам значок уже говорит, что значение есть; решение пользователя, 2026-11-25): у булавки — координаты, у домика — адрес, у горы — высота (в том же виде, что в режиме просмотра фото, п. 4.14), у видео — длительность (`0:47`); у карандаша и «живого фото» — как прежде, «Changed, not saved» и «Live photo».

4.4. Выделение в ленте: клик, Ctrl+клик, Shift+клик, Ctrl+A. В открытой папке всегда выбрано хотя бы одно фото: при открытии папки (не через конкретное фото) выбирается первое фото ленты; последний выбор Ctrl+кликом не снимается; если фильтр (п. 4.13) скрыл все выбранные фото, выбирается первое видимое. При выделении нескольких фото выделенными цветом показываются маркеры всех; карта, строка состояния и стрелки следуют за последним выбранным фото.

4.4.1. Клавиатура: ← и → выбирают предыдущее и следующее фото, Home и End — первое и последнее; лента прокручивается так, чтобы выбранное фото было видно. На краях ленты выбор не переходит на другой конец. ↑ и ↓ (с 0.33.0): в ленте слева — тоже предыдущее и следующее фото, в сетке (п. 4.17) — ряд выше и ниже (ряда ниже нет — последнее фото), в ленте внизу и в просмотре фото из сетки — ничего. PageUp и PageDown (с 0.33.0, предложение Claude, решение пользователя 2026-11-25) — выбор на экран назад и вперёд, лента прокручивается следом: в сетке — на столько рядов, сколько видно, в той же колонке; в ленте слева и внизу — на столько фото, сколько видно; дальше некуда — первое или последнее фото. Так же на карте и в просмотре фото. Так стрелки работают всегда, где бы ни был фокус (на ленте или на карте); карта стрелками не двигается. Исключение — поля ввода: в них стрелки двигают курсор. Shift + эти клавиши (с 0.37.0, решение автора 2026-11-27) — последовательное выделение от опорного фото до нового текущего, как Shift+щелчок (п. 4.4). «+» и «−» (и на цифровом блоке; с 0.37.0, решение автора 2026-11-27) — масштаб карты при любом фокусе (раньше — только когда фокус на карте); в полях ввода — текст, в просмотре фото и сетке — ничего. Ctrl + стрелки (с 0.37.0) — сдвиг карты на часть экрана при любом фокусе (стрелки без Ctrl отданы ленте); в просмотре фото и сетке — ничего.

4.4.2. Связь ленты и карты:
- маркер выбранного фото выделяется другим цветом и рисуется поверх остальных;
- если маркер за краем видимой карты, карта сдвигается к нему без изменения масштаба;
- если маркер спрятан в группу (п. 4.8), карта сдвигается к группе и выделяется группа; масштаб не меняется;
- у выбранного фото без координат на карте ничего не выделяется, карта не двигается;
- клик по маркеру выбирает его фото в ленте и прокручивает ленту к нему;
- двойной клик по миниатюре показывает фото на карте: карта центрируется на его маркере; если маркер спрятан в группу, карта приближается ровно настолько, чтобы он стал виден отдельно, а фото в одной точке раскрываются веером. Масштаб меняется только в этом случае. В режиме просмотра фото (п. 4.14) двойной клик сначала переключает на карту. У фото без координат карта не двигается. То же для текущего фото делают клавиша C (вне полей ввода, без Ctrl; в любой раскладке — по физической клавише) и «View → Show on Map» (недоступен, если у текущего фото нет координат).
- двойной клик по карте (не по маркеру и не по группе), когда у текущего фото нет координат, присваивает ему координаты этой точки; рядом с меткой найденного места — точно её координаты (п. 5.3). Остальные выделенные фото не меняются, карта не приближается. Если у текущего фото координаты есть, двойной клик приближает карту, как обычно.

4.4.3. Выделение на карте прямоугольником: Ctrl+перетаскивание по карте (не по маркеру) рисует рамку, видимую, пока её тянут; по отпусканию выбранными становятся фото, чьи маркеры внутри рамки, — и спрятанные в группах; скрытые фильтром (п. 4.13) не выбираются — у них нет маркеров. Рамка заменяет прежний выбор (добавить к нему можно потом Ctrl+кликом в ленте или по маркеру); текущим становится первое из них в ленте; карта не двигается. Пустая рамка выбор не меняет. Shift+перетаскивание остаётся приближением к области.

4.5. Перетаскивание выделенных миниатюр присваивает им координаты:
- из ленты на карту — координаты этой точки; несколько фото попадают в одну точку;
- внутри ленты на другую миниатюру, без карты, в обе стороны: на фото с координатами — перетаскиваемые получают его координаты; на фото без координат — оно получает координаты перетаскиваемых, если они у всех одинаковые (одно фото или несколько из одной точки). Если у перетаскиваемых разные точки или их нет, на фото без координат бросить нельзя.

- внутри ленты на трек (с 0.28.0) — каждое фото получает своё место на треке по времени съёмки (п. 3.9.7); можно, если время хотя бы одного из них попадает в трек.

Пока фото тянут, миниатюры, на которые бросить нельзя, бледнеют, и курсор над ними — «нельзя» (с 0.28.0): на фото с координатами — можно всегда; на фото без координат — если у перетаскиваемых одни и те же координаты; на трек — по правилу выше.

Если перетаскивается невыделенное фото, переносится только оно и становится выделенным (как в Lightroom); карта при этом остаётся на месте, к маркеру фото не сдвигается (с 0.37.0, решение автора 2026-11-27: иначе карта уезжала к фото с координатами и тянуть было некуда). Перетаскивание, которое закончилось на той же миниатюре без броска (рука дрогнула при щелчке), считается щелчком с теми же Ctrl и Shift (с 0.37.0). Фото, у которого координаты вернулись к тем, что в файле, не считается изменённым.

4.6. Фото, у которых координаты уже есть, показываются на карте и доступны для правки так же, как остальные (пп. 4.5, 4.7).

4.7. Перетаскивание маркера (или миниатюры) на карте меняет координаты всех фото в точке этого маркера. Если маркер принадлежит одному из нескольких выбранных фото (п. 4.4.3), в его новую точку переезжают все выбранные фото с координатами; выбранные без координат не меняются. Маркер, отпущенный рядом с меткой или избранным местом (п. 5.3), встаёт точно на них — так же, как бросок из ленты (с 0.37.0, решение автора 2026-11-27; радиус — как у броска, 24 пикселя, автор подберёт на опыте).

4.8. Близкие маркеры при отдалении группируются в кружок с числом. Клик по группе раскрывает её для выбора одного фото.

4.8.1. Маркеры и группы должны быть хорошо заметны и на обычной карте, и на спутнике. С 0.37.0 (решение автора 2026-11-26, вариант B — как в Google Картах): булавка — красная Google (`#EA4335`) с тонкой тёмной обводкой и тёмной точкой, 28 пикселей; выбранные фото — синие (`#1A73E8`, цвет выделения Google); текущее — синее и на четверть крупнее, поверх всех. Группа — кружок цвета обычной булавки с белой каймой и числом по центру, одного размера (около 26 пикселей; шире только для трёх- и четырёхзначных чисел); группа с выбранным фото — синяя. Рамка выделения на карте (п. 4.4.3) и полоса прогресса окна пакетного режима — тоже синие. Цвета и размер — в настройках; старые значения по умолчанию (`#00E676`, `#FF1744`, 40), записанные в файл настроек, один раз заменяются новыми. Значки на миниатюрах (координаты, адрес, высота, «живое фото», трек) и булавка в счётчике строки состояния — одного спокойного светло-серого цвета, различаются формой; карандаш «не сохранено» — белый (с 0.37.0, решение автора 2026-11-27: без лишнего цвета; палитра — красный фото, синий выбор, жёлтый избранное) (п. 4.3). До 0.37.0: ярко-зелёная булавка 40 пикселей, выбранное — красное, значки — разноцветные.

4.8.2. При наведении на маркер прямо над ним появляется миниатюра фото (пропорции сохраняются), под ней — имя файла мелким шрифтом; вместо прежней подсказки с именем. Размер (по длинной стороне) — в настройках (`map.hoverThumbSize`), по умолчанию 80 px. Если превью нет — заглушка с именем. Над группами, во время перетаскивания маркера и в режиме миниатюр (п. 4.8.3) не показывается.

4.8.3. Режим миниатюр на карте: «View → Thumbnails on Map» (флажок) и клавиша T (вне полей ввода, без Ctrl; в любой раскладке — по физической клавише) переключают «маркеры / миниатюры». Вместо булавки — миниатюра с сохранёнными пропорциями, белой рамкой и маленьким хвостиком снизу, указывающим точку; размер (по длинной стороне) — в настройках (`map.thumbnails.size`), по умолчанию 64 px. Выделенные фото обведены цветом выбранного маркера, текущее — поверх остальных (и в режиме маркеров тоже). Режим запоминается между запусками (п. 7.1). Группа — миниатюра самого раннего фото группы с числом в углу (как в Lightroom); группа с выделенным фото обведена цветом выбранного маркера. Клик, двойной клик и перетаскивание — как у маркеров (пп. 4.4.2, 4.7). Если превью нет — заглушка.

4.9. В окне традиционное меню. Меню «File»: «Open Folder…» (Ctrl+O), «Add Files…» (Ctrl+Shift+O), «Open Recent» (п. 3.1), «Refresh» (F5, п. 3.8), «Save» (Ctrl+S), «Save Selected», «Exit». Пункты сохранения появляются вместе с редактированием (шаг 2). Меню «Edit» (с 0.32.0, решение пользователя 2026-11-25: что Ctrl+C копирует координаты, а не фото, не догадаться): с 0.37.0 первыми — «Undo» (Ctrl+Z) и «Redo» (Ctrl+Y), п. 6.6; «Copy Coordinates» (Ctrl+C, п. 4.10), «Paste Coordinates» (Ctrl+V, пп. 4.10, 4.12), «Delete Coordinates» (Ctrl+Del, п. 6.6); «Take off the Strip» (Del, п. 6.6); «Select All» (Ctrl+A, п. 4.4); с 0.37.0 последним — «Find Place» (Ctrl+F, п. 5.3). Поведение — как у клавиш; клавиши обрабатывает окно, поэтому в полях ввода Ctrl+C, Ctrl+V и Ctrl+A работают с текстом. Недоступны: «Copy» — у текущего фото нет координат; «Paste» и «Delete Coordinates» — не выбрано ни одного фото (у «Delete» — и ни одного с координатами); «Take off the Strip» — ничего не выбрано; на время сохранения — всё, кроме «Copy» и «Select All». Меню «Tools»: флажки «Get Address» (п. 5.5) и «Get Altitude» (п. 5.6); «Language» (п. 2.3); «Open Settings File» (п. 8.2) и «Open Log Folder» — папка логов (п. 6.9) в Проводнике. Меню «View» (с шага 2): «Photo View» (пробел, п. 4.14), «Show on Map» (C, п. 4.4.2), «Thumbnails on Map» (T, флажок, п. 4.8.3); «Strip Position» (подменю «Bottom» / «Left», п. 4.1) и «Grid» (G, флажок, п. 4.17); «Filter: …» — один пункт с названием включённого фильтра («Filter: All Photos», «Filter: With Coordinates», «Filter: Without Coordinates», «Filter: Modified»); щелчок и клавиша F (вне полей ввода, без Ctrl; в любой раскладке — по физической клавише) включают следующий фильтр по кругу, пустые пропускаются (п. 4.13); название в пункте меняется вместе с фильтром, откуда бы он ни был включён: щелчком по пункту, клавишей F или кнопкой счётчика; недоступен, если, кроме «всего», все фильтры пусты (с 0.39.0, решение автора 2026-11-28: четыре пункта делали меню «View» длинным). Меню «Help»: «Keyboard Shortcuts» (F1, п. 4.15) и «About GeoPhotos» — окно поверх программы (как справка): версии программы, exiftool, Electron и Node.js; без путей к настройкам и логам — они в меню «Tools»; ссылки на лицензию программы (MIT) и на лицензии сторонних компонентов (THIRD-PARTY-NOTICES.txt рядом с программой, собирается при сборке). Закрывается по Esc, крестиком или кликом вне окна.

4.10. Копирование и вставка координат через буфер обмена. Ctrl+C копирует координаты, адрес и высоту текущего фото (выделение из нескольких фото — только текущего): в буфер — координаты текстом, адрес и высоту программа запоминает сама. Ctrl+V, пока в буфере тот же текст, вставляет все три (нет адреса или высоты у исходного — нет и у вставленных; при включённых режимах они получаются, пп. 5.5, 5.6); если текст в буфере другой (например, из Google Maps) — только координаты. Если у текущего фото нет координат — ненадолго сообщение «The photo has no coordinates», буфер не меняется. Ctrl+V присваивает выделенным фото координаты из буфера, если там удаётся распознать пару координат (скопированную с фото по Ctrl+C, из Google Maps или другого источника) по п. 4.12; вставляется то, что скопировано последним. Если не удаётся, ненадолго показывается сообщение «No suitable data in the clipboard» в строке состояния; координаты не меняются. Если новая точка за краем карты, карта сдвигается к ней без смены масштаба. Так Ctrl+C и Ctrl+V работают, когда фокус на ленте или карте, и в режиме просмотра фото, в любой раскладке (по физической клавише); в полях ввода это обычные копирование и вставка текста. Отдельных пунктов меню нет; строки — в справке (п. 4.15).

4.11. Ручного ввода координат в поля нет и не будет.

4.12. Разбор координат нестрогий: принимается всё, что можно однозначно понять как широту и долготу.
- Порядок: широта, затем долгота. Широта от −90 до 90, долгота от −180 до 180 — единственная жёсткая проверка.
- Если букв N/S/E/W нет, а первое число по модулю больше 90 и второе нет, считается, что порядок «долгота, широта», и числа меняются местами. Если буквы есть, они сами указывают, где широта.
- Запись, в которой непонятно, какая запятая разделяет числа (`49,84193, 24,03152`), не принимается.
- Десятичные градусы: `49.84193, 24.03152`, `-33.8568 151.2153`, `49,84193 24,03152` (запятая как дробный разделитель, если между числами пробел или точка с запятой).
- Угловой вид — градусы-минуты-секунды или градусы-минуты: `49°50'30.9"N 24°01'53.5"E`, `49°50.516'N 24°1.891'E`, `N 49 50 30.9 E 24 1 53.5`.
- Буквы N/S/E/W (и С/Ю/В/З) — до или после числа, в любом регистре. Знаки °, ', " и их варианты (′, ″, ’, ”) можно не ставить.
- Лишние пробелы, скобки и подписи вроде `lat:`, `lon:` игнорируются.

4.13. Информация о фото и о папке:
- строка состояния внизу окна: имя, дата съёмки и размер файла текущего фото, у видео — и длительность (при выделении нескольких — и их число). Имя — светлым, остальное — тем же цветом приглушённо, части разделены тусклой точкой: `IMG_3381.jpg   03.07.2010 21:19:56 · 6,4 МБ`. Откуда взята дата (п. 4.2), нигде не помечается. Даты везде (строка состояния, подсказка, режим просмотра) — в региональном формате Windows, как в Проводнике; дата из имени файла без времени — только дата; координаты не показываются (они — по Ctrl+C, п. 4.10, и в режиме просмотра фото, п. 4.14), «изменено» — значок в ленте (п. 4.3); счётчик «всего / с координатами / без координат / изменено» (только фото: треки в счётчик и фильтры не входят, п. 3.9.3);
- части счётчика — мини-кнопки, фильтр ленты: значок (те же, что в миниатюрах: булавка — с координатами, карандаш — изменено; для «всего» — значок «фото»; для «без координат» — серая перечёркнутая булавка) и число; название и пояснение — в подсказке. «С координатами», «без координат» и «изменено» показывают только эти фото, «всего» — все. Включённый фильтр обведён цветом своего значка, «всего» — белым. Повторный клик по включённому фильтру его снимает. Клавиша F и пункт «View → Filter: …» перебирают фильтры по кругу (с 0.39.0, п. 4.9). Фильтр, под который не попадает ни одно фото, недоступен; если включённый фильтр стал пустым (например, «изменено» после сохранения), включается «всего». Фильтр действует на ленту и на маркеры карты: у скрытых фото маркеров нет. По клику на кнопку фильтра карта показывает все видимые маркеры, как при открытии папки (п. 5.2); если их нет, карта не двигается. Изменения фото, которые меняют состав фильтра (правка, сохранение), карту не двигают. Перетаскивание маркера (п. 4.7) переносит только видимые фото в его точке. Фильтр обновляется сразу при изменении фото. Скрытые фото снимаются с выделения; Ctrl+A, Shift+клик и стрелки работают по видимым фото. При открытии папки фильтр сбрасывается;
- при наведении на миниатюру — подсказка с именем, датой съёмки и координатами; у видео — и длительность (`0:47`);
- в заголовке окна — имя открытой папки (без папки — папки первого добавленного файла, п. 3.1; добавленные файлы из других папок заголовок не меняют; без пути: на панели задач длинный путь обрезал бы имя; у корня диска — диск, `E:\`), затем «GeoPhotos»; `*` в начале, если есть несохранённые изменения: `* master — GeoPhotos`.

4.14. Режим просмотра фото: пробел (вне полей ввода) и «View → Photo View» переключают основную область между картой (по умолчанию) и текущим фото. Фото показывается на месте карты, вписанным целиком, без приближения; лента и строка состояния остаются, ← → листают фото. В левом верхнем углу — имя файла и дата съёмки; под ними координаты с высотой (целые метры) и адрес, если они есть. Источник изображения — тот же, что у миниатюры (п. 3.3.4), крупнее; если показать нельзя — заглушка с именем файла. У «живого» фото сначала один раз проигрывается его ролик (п. 3.3.7). У видео — крупный системный кадр (п. 3.3.6) и кнопка «Open in Player»: ролик открывается программой Windows по умолчанию; если кнопка окажется неудобной — её уберут. Режим и фильтр между запусками не запоминаются. На треке пробел показывает просмотр трека (п. 3.9.6). С 0.36.0 под именем и датой — модель камеры или телефона из файла, как она записана («iPhone 14 Pro Max», «Canon EOS 5D Mark II»; производитель не добавляется); нет модели — строки нет. Выдержка, диафрагма, ISO, объектив не показываются (решение автора 2026-11-25).

4.15. Справка «Keyboard Shortcuts» (F1 или «Help → Keyboard Shortcuts»): окно поверх программы со списком клавиш, действий мышью и отметок (значков). Закрывается по Esc, крестиком или кликом вне окна; пока оно открыто, клавиши программы не действуют. Тексты — в файлах локализации (п. 2.3); список ведётся в коде вместе с клавишами программы.

4.16. Программа всегда тёмная, при любой теме Windows (с 0.32.1): окно, а также строка меню, заголовок окна, полосы прокрутки и окна Windows, которые открывает программа (выбор файлов, сообщения). Светлой темы и переключателя тем не будет (решение 2026-11-25): в программах для фото тёмный интерфейс — стандарт. Пункт строки меню при переходе по ней с клавиатуры (Alt, стрелки) Windows в тёмной теме отмечает только бледными вертикальными чёрточками по бокам; это ограничение Windows и Electron, не исправляется (решение автора 2026-11-28): иначе нужна своя отрисовка меню вместо системной (`make-project.md`, п. 2).

4.17. Сетка миниатюр (с 0.33.0): G и «View → Grid» (флажок) разворачивают ленту на всё окно вместо карты: миниатюры в несколько рядов — чтобы при большом числе фото проще находить и выбирать. Выход — G ещё раз или Esc (если открыты справка или «About GeoPhotos», Esc сначала закрывает их); после выхода — карта, выбор остаётся. Выбор, Ctrl/Shift+клик, Ctrl+A, Del — как в ленте; клавиши — п. 4.4.1; двойной щелчок и C — выход из сетки и показ фото на карте (п. 4.4.2). Пробел — просмотр фото на всё окно, пробел ещё раз — обратно в сетку, Esc — к карте. Перетаскивать на карту из сетки нельзя (карты не видно); на другие миниатюры — можно (п. 4.5). Размер миниатюр в сетке (с 0.34.0) — Ctrl+колесо мыши, Ctrl + «+» / «−», Ctrl+0 — обычный: от 80 до 240 пикселей, шаг 20, по умолчанию 120; запоминается между запусками (п. 7.1); у ленты внизу и слева — свой размер (с 0.37.0, п. 4.1). Сама сетка не запоминается между запусками. Карты на всё окно (без ленты) не будет: польза мала, а это лишняя клавиша и пункт меню (решение пользователя 2026-11-25).

4.18. Стартовый экран (с 0.34.0, решение автора 2026-11-25): когда ничего не открыто — поверх карты по центру кнопка «Open Folder…» (как в меню), под ней последние папки (щелчок открывает, как «Open Recent», п. 3.1), подсказка «or drop a folder or photos onto the window». Исчезает, как только что-то открыто.

4.19. Контекстное меню (с 0.34.0, решение автора 2026-11-25) — правый щелчок по миниатюре (в ленте и в сетке) или по маркеру одного фото на карте; клавиша «Меню» или Shift+F10 — для текущего фото (меню — у его миниатюры, если она видна). Щелчок по невыбранному фото сначала выбирает его одно; по выбранному — выбор не меняется, фото становится текущим (как в Проводнике). Пункты: «Show on Map», «Open in Google Maps» (с 0.36.0: только у фото с координатами — браузер открывает Google Карты на точке фото; координаты уходят в Google только по этому щелчку), «Copy Coordinates», «Paste Coordinates», «Delete Coordinates», «Take off the Strip» — как в меню «Edit» и «View» (п. 4.9), с теми же клавишами и условиями доступности; затем «Show in Explorer» (папка, в ней выделен файл текущего фото) и «Open in Another Program» (текущее фото, видео или трек — программой Windows для этого типа файлов). У трека — только «Show on Map», «Take off the Strip» и два последних. На группе маркеров (кружок с числом, п. 4.8) меню нет; правый щелчок по пустой карте ставит метку с её меню, у метки и избранных мест — свои меню (с 0.37.0, п. 5.3).

4.20. Направление съёмки (с 0.35.0, решение автора 2026-11-25): если в фото записано, куда смотрела камера (`GPSImgDirection` в EXIF или XMP, пишут телефоны — iPhone), у маркера текущего фото на карте — полупрозрачный приглушённо-синий сектор 50° в эту сторону, гуще у маркера, светлее к краю, с тонким контуром (решение автора: не красный и не кричащий, но заметный); только от масштаба карты 15 (кварталы и улицы) — при отдалении сектор в километры ничего не говорит (решение автора). Только у текущего фото и только пока его маркер на карте сам по себе (не в группе, п. 4.8); у фото без направления (фотоаппараты) — ничего. Направление не меняется и не записывается программой; при удалении координат (Ctrl+Del) удаляется вместе с GPS-блоком (п. 6.6).

## 5. Карта

5.1. Тайлы карты загружаются из интернета, без ключей доступа. Источники с переключением:
- обычная карта — OpenStreetMap;
- спутник — Esri World Imagery;
- спутник — Google, по прямым адресам тайлов. Условия Google такой доступ не разрешают, и Google может его в любой момент закрыть; тогда остаётся спутник Esri;
- топографическая карта — OpenTopoMap, последней в списке. Любой источник можно выбрать при любом масштабе: карта приближается до наибольшего масштаба среди источников, а у источника с меньшим максимальным масштабом (у OpenTopoMap — 17) на крупных масштабах показываются его увеличенные тайлы.

Адреса тайлов, подписи и максимальный масштаб каждого источника — в настройках, источник меняется без изменения кода. На карте показывается подпись правообладателей (attribution).

5.2. При открытии папки карта показывает все её фото с координатами. Если таких нет — карта остаётся на прежнем месте (п. 7.3). Центр и масштаб из настроек — только при самом первом запуске, пока сохранённого места нет (п. 7.1).

5.3. Поиск места по названию или адресу — через публичный сервис Nominatim (OpenStreetMap).
- Поле поиска на карте с подсказкой «Find a place»; запрос отправляется по Enter, без поиска по мере ввода (так требуют правила Nominatim).
- Результаты — списком. Выбор результата перемещает карту к этому месту и ставит там временную метку; координаты фото не меняются. Фото, брошенное рядом с меткой, получает точно её координаты.
- Правила использования Nominatim соблюдаются: не чаще одного запроса в секунду, программа называет себя в заголовке User-Agent.
- Адрес сервиса поиска — в настройках. Свой сервер Nominatim для поиска не используется: прямой поиск он не умеет.
- Без интернета поиск недоступен.
- **Поле поиска** (с 0.37.0, решения автора 2026-11-27): после выбора места поле очищается, фокус переходит на карту (клавиши карты «+» / «−» работают сразу) — карта показывает место с меткой. Ctrl+F (и «Edit → Find Place») ставит курсор в поле и сразу показывает список мест (ниже), первая строка в нём подсвечена — Enter ведёт к этому месту; текст, оставшийся в поле от прежнего набора (ушли на карту, ничего не выбрав), Ctrl+F стирает — каждый раз чистое поле (решение автора 2026-11-27); Ctrl+F срабатывает откуда угодно (решение автора 2026-11-27: самый частый вход к избранному): закрывает справку и «About GeoPhotos», выходит из просмотра фото, сетки и полей ввода (недописанное переименование избранного отменяется); только в самом поле поиска набираемый текст не трогает; стрелки двигают подсветку, набор текста закрывает список и Enter ищет набранное; Esc закрывает список и возвращает фокус карте. Крестик в поле только стирает набранный текст, метку не трогает.
- **История поиска** (с 0.37.0, решение автора 2026-11-25, по предложению Claude; уточнения — 2026-11-27). Щелчок в пустое поле поиска или Ctrl+F показывает под ним места, к которым переходили раньше, — до 5, сверху последнее; щелчок по месту ведёт к нему, как выбор из результатов поиска. Запоминаются только места, к которым перешли (выбрали из результатов: название и координаты, без повторного запроса), а не набранные запросы; повторное место поднимается наверх, а не дублируется. Текущее место (на нём стоит метка) в списке не показывается — это настоящее, а не история; оно появляется в истории, когда перестаёт быть текущим: выбрано другое место, метка убрана или заменена, открыта другая папка, программа закрыта (хранится 6 мест, показывается до 5). У строк — номера 1…5 (решение автора 2026-11-27): цифра печатается в поле как обычно, но пока в поле ровно одна цифра и в истории есть место с этим номером, список не закрывается и эта строка подсвечена — Enter ведёт к месту; дальше набор («1 Мая») — обычный запрос, без исключений. Alt + цифра в открытом списке — сразу к месту одним нажатием; номер без места ничего не делает. У каждого места — звёздочка (в избранное); крестика (убрать из истории) нет: история сама вытесняет старое, нужное — в избранное. Хранится между запусками в файле состояния (п. 7.5).
- **Избранные места** (с 0.37.0, решения автора 2026-11-27). В том же списке под чертой, после истории — избранные места в порядке добавления (новое — в конец; номера не сдвигаются при переименовании), без ограничения числа; хранятся в файле состояния (п. 7.5), от сеанса и папки не зависят. У первых девяти — номера 1…9 (подсказка «Ctrl+N»): Ctrl+1…9 переходит к избранному месту при любом фокусе, из просмотра фото и сетки — сначала к карте; номер без места ничего не делает; Ctrl+0 остаётся сбросом размера миниатюр (п. 4.1). Звёздочка у места в истории переносит его в избранное; снятая звёздочка у избранного удаляет его (в историю оно не идёт; ошибку исправляет Ctrl+Z). Щелчок по избранному месту ведёт к нему (в историю оно не идёт). Переименовать в списке — F2 на выбранной строке: название становится полем ввода, текст выделен; Enter — сохранить, Esc — отменить (двойного щелчка нет: первый щелчок уже ведёт к месту).
  - На карте избранные места видны всегда — жёлтый кружок с белой звездой (не булавка: не путать с фото), поверх маркеров и миниатюр фото (иначе миниатюры их закрывают), но под группами маркеров (кружок с числом): группа, брошенная на избранное место, остаётся доступной для щелчка (решение автора 2026-11-27). Наведение — название. Значок перетаскивается мышью (место сдвигается; ошибку исправляет Ctrl+Z). Фото, брошенное рядом, встаёт точно на место, двойной щелчок по значку ставит туда текущее фото — как у метки. Правый щелчок — меню: «Copy Coordinates», «Open in Google Maps», «Rename…», «Remove from Favorites». «Rename…» открывает над значком поле с выделенным названием (Enter — сохранить, Esc — отменить).
  - Отменяются Ctrl+Z (п. 6.6) все изменения избранного: добавление, сдвиг, переименование, удаление.
- **Метка** (с 0.37.0, решения автора 2026-11-27). Метка на карте одна: её ставит выбор места в поиске или правый щелчок по пустой карте (в точке щелчка, сразу открывается её меню). Вид — кольцо цвета маркеров (красное: форма говорит, что это не фото), поверх маркеров фото. Метка перетаскивается мышью сама по себе, фото это не трогает; название (у найденного места) остаётся. Наведение — название или координаты. Правый щелчок — меню: «Copy Coordinates», «Open in Google Maps», «Add to Favorites», «Remove Mark». «Add to Favorites» делает метку избранным местом: название — найденного места, у точки с правого щелчка — адрес точки (Nominatim, как п. 5.5: улица с домом и город), без интернета — координаты; сразу над новым значком открывается поле названия с выделенным текстом (как «Rename…»). Метка исчезает при новом поиске, новой метке, «Remove Mark» и открытии другой папки. Фото, брошенное рядом с меткой (из ленты или маркером по карте, п. 4.7), получает точно её координаты; двойной щелчок по метке ставит туда текущее фото.
- В справке Ctrl+F описан как вход и в поиск, и в список мест (история и избранное).

5.5. Адрес (обратное геокодирование). Меню «Tools», флажок «Get Address». Пока он включён, программа получает адрес для всех фото открытой папки, у которых есть координаты, но нет адреса, — в том числе сразу после смены координат.
- Сервис — Nominatim, по умолчанию публичный nominatim.openstreetmap.org; адрес сервиса и пауза между запросами — в настройках (`geocode.url`, `geocode.minIntervalMs`, по умолчанию 1000 мс: правила публичного сервера — не чаще 1 запроса в секунду). Поиск мест (п. 5.3) и адреса на одном сервере делят это ограничение. Фото в одной точке получают адрес одним запросом. Точка, по которой ответа нет (ошибка, тайм-аут 15 с) или адреса нет (море), до переоткрытия папки или повторного включения флажка не запрашивается снова.
- Язык названий — язык интерфейса, затем английский.
- Поля — как в Lightroom, в XMP: страна (photoshop:Country), код страны (Iptc4xmpCore:CountryCode), область (photoshop:State), город (photoshop:City; из city / town / village), место (Iptc4xmpCore:Location; улица с номером дома). Пишутся в XMP файла и в существующий XMP рядом; RAW — только в XMP рядом. Названия мест в IPTC при записи удаляются, чтобы не расходились с XMP; читаются, если XMP пуст (порядок — как у координат, п. 3.7).
- Запросы идут очередью в фоне; в строке состояния — сколько осталось. Если сохранить, пока очередь не пуста, — вопрос с числом оставшихся фото и оценкой времени: «Wait and save» (ход, затем сохранение), «Save without them», «Cancel». Если сервис не ответил (ошибка, тайм-аут 20 с), точка запрашивается снова в фоне — через 30 с, 2 мин и 10 мин, после этого — до переоткрытия папки или повторного включения флажка; ошибки — в лог. Пока точки ждут повтора, они считаются в строке состояния, а время — до ближайшего повтора. Точка без адреса (море) не повторяется.
- Полученный адрес — несохранённое изменение (п. 4.3), пишется по «Save». Адрес, уже записанный в файле, читается и показывается.
- Состояние флажка запоминается между запусками (п. 7.1).

5.6. Высота. Меню «Tools», флажок «Get Altitude» — как «Get Address» (п. 5.5): для всех фото папки с координатами и без высоты, отдельной очередью рядом с адресами; в строке состояния и в вопросе при сохранении — сколько адресов и высот осталось. Высота берётся из интернета: Open-Meteo Elevation API (без ключа, рельеф Copernicus DEM GLO-90, шаг 90 м; до 100 точек за запрос, не чаще запроса в секунду; бесплатно для некоммерческого использования — до 10 000 запросов в день; адрес сервиса — в настройках, `elevation.url`). Условия сервиса требуют указать источник — строка в «About». Пишется туда же, куда координаты: EXIF GPSAltitude/GPSAltitudeRef файла, XMP с координатами (встроенный, рядом), у RAW — XMP рядом. Высота, уже записанная в файле (например, телефоном), читается (порядок — как у координат, п. 3.7) и не запрашивается — кроме высоты ровно 0: её часто пишут устройства, не знавшие высоты. Такая высота проверяется в той же очереди: если рельеф в точке не ближе 10 м к уровню моря, 0 заменяется высотой рельефа (несохранённое изменение, лог); если ближе (берег моря) — 0 остаётся и до переоткрытия папки не проверяется снова. Так же в пакетном режиме (п. 10).

5.4. Ввод координат — вставкой из буфера обмена (пп. 4.10, 4.12). Ручного ввода в поля нет.

## 6. Запись результата

6.1. Запись — отдельное действие через меню (п. 4.9): «Save» для всех изменённых фото, «Save Selected» для выбранных.

6.2. Пишутся широта и долгота, адрес (п. 5.5) и высота (п. 5.6), и их удаление. При смене координат прежние адрес и высота фото удаляются (они стали бы неверными); если режим получения включён, вместо них получаются новые.

6.3. Обычные форматы (п. 3.3.2) — в EXIF самого файла через exiftool; остальные поля не меняются. Если во встроенном XMP файла или в XMP рядом уже есть координаты, они обновляются теми же значениями, чтобы источники не расходились и после записи по п. 3.7 читались новые координаты. Если exiftool сообщает об ошибке, файл остаётся прежним, ошибка — по п. 6.7. Изменять оригиналы всех форматов из п. 3.3.2 можно. Резервные копии exiftool (`*_original`) не создаются и не настраиваются.

Видео из первого списка п. 3.3.6 — в метаданные QuickTime самого файла, туда, где их хранят телефоны: Keys (iPhone) и UserData (Android), координаты с высотой; прежние координаты QuickTime из всех мест удаляются. Адрес — в XMP файла; GPS в XMP файла — если он там уже был. EXIF и IPTC у видео не пишутся, остальные поля не меняются. Время съёмки в файле не меняется (п. 4.2), время изменения файла сохраняется (у некоторых видео это единственная дата). exiftool при этом переписывает файл — нужно свободное место на диске размером с ролик; не хватит — ошибка записи по п. 6.7.

6.4. RAW (п. 3.3.3), кроме DNG, — только в XMP-файл рядом, сам RAW не изменяется. Существующий XMP дополняется, а не перезаписывается. Если XMP нет — создаётся с минимальной информацией о геопривязке. Имя XMP — как в Lightroom: имя RAW-файла с расширением `.xmp` (`IMG_0001.CR2` → `IMG_0001.xmp`). Так же — видео из второго списка п. 3.3.6 (`MVI_0001.AVI` → `MVI_0001.xmp`); сам ролик не меняется.

6.5. При выходе или открытии другой папки с несохранёнными изменениями — предупреждение, что изменения не сохранены, с выбором: сохранить, не сохранять, отмена. Если при «сохранить» часть файлов записать не удалось, программа остаётся в текущей папке.

6.6. Undo (с 0.37.0, решение автора 2026-11-25; раньше считался ненужным): Ctrl+Z отменяет последнее изменение координат, Ctrl+Y и Ctrl+Shift+Z повторяют отменённое; в меню «Edit» первыми — «Undo» и «Redo», без пояснения, что отменится (решение автора: оно почти всегда одно и то же и только расширяет меню; что отменено, пишет строка состояния); недоступны, когда нечего, и на время сохранения. Отменяются изменения координат до сохранения и (с 0.37.0) изменения избранных мест (п. 5.3): перенос маркера, бросок на карту, на фото или на трек, вставка, Ctrl+Del, двойной щелчок по карте; адрес и высота возвращаются вместе с координатами. Один шаг — одно действие (маркер увёз 12 фото — шаг вернёт все 12; бросок группы на трек — один шаг). Глубина — без ограничения. История очищается при сохранении, F5, открытии другой папки, добавлении и убирании файлов: записанное в файлы не отменяется (старые значения — в логе, п. 6.9). Убирание из ленты (Del) не отменяется — вернуть фото можно через «Add Files…». После отмены затронутые фото становятся выбранными (карта показывает текущее из них, если оно за краем), в строке состояния — «Undone: …». Шаги с избранным живут в той же истории и очищаются вместе с ней. В полях ввода Ctrl+Z — отмена набора текста. «Revert» (отмена всех несохранённых изменений) не нужен — его заменяет Undo. Клавиши (вне полей ввода; с 0.26.0, решение пользователя — одна клавиша одно действие):
- **Del** убирает выделенные элементы ленты — фото или трек — из ленты (п. 3.1); файлы на диске не меняются. Если у кого-то из них есть несохранённые изменения — вопрос «n photo(s) have unsaved changes. Take them off the strip?» («Take Off» / «Cancel»); иначе без вопроса. Текущим становится следующий элемент ленты.
- **Ctrl+Del** удаляет у выделенных фото координаты, адрес и высоту — несохранённое изменение до «Save», без подтверждения.

(В 0.25.0 Del удалял координаты, а у фото без координат — убирал их из ленты.)

Удаление координат (Ctrl+Del): при записи из файла удаляются весь GPS-блок EXIF (координаты, высота, время GPS), GPS-поля встроенного XMP и XMP рядом, названия мест в XMP и IPTC (п. 5.5); остальные поля не меняются. Сам RAW не меняется (п. 6.4): координаты внутри RAW-файла удалить нельзя — такое фото попадает в список ошибок записи. Так же видео из второго списка п. 3.3.6 с координатами внутри файла и видео, у которого координаты — из трека (трек не удаляется). У видео из первого списка удаляются координаты QuickTime и GPS и места в XMP. Удаление всех метаданных не нужно.

6.7. Ошибки (битый файл, файл только для чтения, ошибка exiftool) — диагностика в окне и лог-файл.

6.8. Ход и итог записи:
- если файлов много, показывается ход записи (n из N);
- отметка «изменено, не сохранено» снимается только у успешно записанных фото;
- по окончании — список файлов, которые записать не удалось, с причиной;
- после записи координаты перечитываются из файла по п. 3.7 и показываются заново.

6.9. Лог-файл:
- лежит в папке `logs` в `app.getPath('userData')`;
- пишутся: открытие папки, ошибки чтения и записи, каждая запись координат (файл, старые и новые координаты) — по логу можно вручную вернуть прежние значения;
- уровень подробности — в настройках;
- размер ограничен: при превышении файл переименовывается, хранится несколько последних;
- имя файла — geophotos.log, архивные — geophotos.1.log, geophotos.2.log…; файлы со старым именем main.log (до 0.15.0) удаляются при запуске;
- если geophotos.log нельзя записать (открыт в другой программе с запретом записи), сеанс пишет в запасной файл geophotos-<дата>-<время>-<процесс>.log; при запуске остаются только последние такие сеансы (столько же, сколько хранится файлов лога), остальные удаляются.

## 7. Состояние между запусками

7.1. При выходе сохраняется состояние программы, при следующем запуске оно восстанавливается:
- проект (п. 3.1): открытая папка, добавленные файлы и убранные из ленты файлы папки; текущее фото (то, что в строке состояния; остальное выделение не восстанавливается). Если папки нет — программа запускается без неё (добавленные файлы остаются); пропавшие добавленные файлы выпадают; если нет текущего фото — выбирается первое; об этом только запись в логе;
- положение и размер окна, развёрнуто ли оно; если сохранённое место за пределами всех мониторов — положение по умолчанию;
- место и масштаб карты: при запуске с папкой прошлого сеанса карта такая же, как при выходе (а не по п. 5.2); при открытии другой папки — по п. 5.2 и п. 7.3; место из настроек (п. 5.2) — только когда сохранённого места ещё нет;
- выбранный источник карты (п. 5.1);
- режим отображения на карте (маркеры / миниатюры, п. 4.8.3);
- флажки «Get Address» (п. 5.5) и «Get Altitude» (п. 5.6);
- положение ленты (п. 4.1) и размер миниатюр в сетке (п. 4.17). Сама сетка не запоминается: программа всегда запускается с картой;
- позиция прокрутки ленты — только для папки прошлого сеанса.

7.2. Папка, переданная параметром запуска, важнее сохранённого проекта; файлы в параметрах запуска (без папки) начинают новый проект из них. Если сохранённой папки больше нет, программа запускается без открытой папки.

7.3. При открытии папки, в которой нет фото с координатами, карта остаётся на прежнем месте и в прежнем масштабе (вместо места из настроек по п. 5.2).

7.4. Несохранённые изменения координат в состояние не входят: они сохраняются только через «Save» (п. 6).

7.5. Состояние хранится в служебном файле в `app.getPath('userData')`, отдельно от настроек. Пользователь его не правит. Если файл повреждён, программа запускается с состоянием по умолчанию.

8.1. Требования к конфигурации — в `tz-config.md`. Формат, схемы, чтение с проверкой и запись (`tz-config.md`, пп. 1–5) действуют с шага 1.

8.2. Настройки правятся вручную в любом текстовом редакторе; встроенных редакторов нет. Пункт меню «Open Settings File» открывает пользовательский конфиг (`tz-config.md`, п. 6).

8.3. Пользовательский конфиг накладывается на конфиг по умолчанию по полям: поля, которых в нём нет, берутся по умолчанию. Если пользовательского конфига нет, действуют значения по умолчанию. «Open Settings File» создаёт его как полную копию настроек по умолчанию с пояснением к каждому полю (`tz-config.md`, п. 6.3), чтобы все настройки и их значения были видны и менялись на месте. Известное ограничение: если в новой версии программы изменится значение по умолчанию, в уже созданный файл оно не попадёт.

8.4. Если конфиг не прошёл проверку, выводится сообщение по `tz-config.md`, п. 4.3, и для этого файла действуют значения по умолчанию.

8.5. Изменения настроек применяются после перезапуска программы.

8.6. Настройки:

- цвета маркеров (обычный, выбранный) и их размер (п. 4.8.1); размер миниатюры при наведении (п. 4.8.2) и миниатюр на карте (п. 4.8.3);
- уровень подробности лога (п. 6.9);
- адрес сервиса поиска мест (п. 5.3);
- вложенные папки (п. 3.2);
- адрес сервиса адресов и пауза между запросами (п. 5.5);
- адрес сервиса высот (п. 5.6);
- цвета треков и масштаб, с которого видны названия путевых точек (п. 3.9.5);

## 9. Этапы

Программа развивалась шагами 1–2 (версии 0.1.0 и 0.2.0); с версии 0.3.0 каждая фича — очередная подверсия (`make-project.md`, п. 5). Каждая версия должна быть рабочей и архитектурно не противоречить следующим. Чем проще фича, тем лучше.

Пп. 9.1–9.2 — история и критерии готовности первых версий. Версия считается готовой, когда пройдены её критерии на тестовой папке. Тестовая папка: JPEG с координатами и без, HEIC с телефона, CR2 с XMP рядом и без, DNG, PNG или TIFF, фото без даты съёмки, битый файл, файл только для чтения.

### 9.1. Шаг 1 — просмотр (версия 0.1.0)

Только показ: фото с координатами отображаются на карте маркерами, ничего не изменяется.

- меню «File» с пунктами «Open Photo…», «Open Recent», «Open Settings File» и «Exit» по п. 4.9;
- открытие папки всеми способами п. 3.1 (фото в окне выбора, последние папки, перетаскивание, параметр запуска), только сама папка, без вложенных;

Критерии готовности:

- в ленте все фото тестовой папки по времени съёмки, у каждого миниатюра или заглушка;
- фото с координатами отмечены в ленте и стоят маркерами на карте в правильных местах (сверить с другим источником, например Lightroom или Google Maps);
- три источника карты переключаются; близкие маркеры группируются; подписи правообладателей видны; маркеры и группы хорошо заметны на обычной карте и на спутнике;
- выбор фото в ленте (кликом и стрелками ← → Home End, в том числе когда фокус на карте) выделяет его маркер или группу и сдвигает карту к ним; клик по маркеру выбирает фото в ленте;
- битый файл не мешает работе, ошибка — в окне и в логе;
- «Open Settings File» открывает пользовательский конфиг, при его отсутствии создаёт по `tz-config.md`, п. 6.3;
- язык меняется правкой настроек и перезапуском;

- **0.28.0 — треки: привязка.** По п. 3.9.7: отметка места на треке для текущего фото без координат, «примагничивание» при броске на карту, бросок фото на трек в ленте; недоступные цели при перетаскивании (п. 4.5). Что решено: у текущего фото без координат, но со временем съёмки на треке подсвечивается вероятная точка — место трека в момент съёмки (с погрешностью; на всех треках, где она есть). Фото, брошенное на карту рядом с ней, «примагничивается» к ней; брошенное в стороне — получает точку броска. Фото, брошенные в ленте на трек (как на фото, п. 4.5), получают точку трека в момент своей съёмки — каждое свою; фото с координатами — тоже (бросок сознательный, координаты заменяются); фото без времени или вне трека не меняются, без сообщений. Там же — недоступные цели при перетаскивании: миниатюры, на которые бросить нельзя (например, фото без координат, когда тянут фото без координат), бледнеют, курсор над ними — «нельзя». Треки из видео (GoPro, регистраторы) — отдельной фичей, когда будут тестовые файлы.

Распространение — обычные фичи, а не заключительный этап (решение пользователя, 2026-11-25). Разработка идёт без конца, пока есть идеи, а каждая выпущенная версия рабочая и может оказаться последней. Поэтому выпуск, установка и сборка из исходников делаются сейчас, один раз, и дальше работают для каждой версии. Они идут в одной очереди с новыми фичами, порядок решает пользователь.

Уже сделано (решение пользователя, 2026-11-24, после 0.25.0): репозиторий публичный; готовая программа выкладывается в GitHub Releases как zip (`GeoPhotos-<версия>-win-x64.zip`, внутри папка `GeoPhotos` — содержимое `dist\win-unpacked`, без exiftool); установка — распаковка, инструкция в README (раздел Installation): распаковать, запустить, SmartScreen, «Install for GeoPhotos», обновление и удаление. Архивы исходников (Source code) GitHub добавляет к релизу сам.

Следующие (номер — когда начинается работа; подробности обсуждаются перед ней):
- **Сборка релизов в GitHub Actions; сборка из исходников.** По тегу `vX.Y.Z` программа собирается в облаке GitHub, а не на компьютере пользователя; к zip — аттестация происхождения: любой может проверить (`gh attestation verify`), что файл собран из этого тега публичного репозитория. Тесты (unit и интеграционные с настоящим exiftool) — при каждом push, на Windows и на Ubuntu: окно для них не нужно, а так заранее видно, что ломается под Linux (п. 9.4).   - **Стартовый экран** — когда ничего не открыто: поверх карты по центру кнопка «Open Folder…», под ней последние папки (щелчок открывает, как «Open Recent»), подсказка «or drop a folder or photos onto the window». Исчезает, как только что-то открыто.
  - Разделителей по дням в сетке не будет (решение автора 2026-11-25).
- **0.35.0 — одно окно, последние папки на значке, направление съёмки** (решение автора 2026-11-25, по предложению Claude; сделано — пп. 2.6, 3.1, 4.20).
  - **Одно окно.** GeoPhotos работает в одном экземпляре. Повторный запуск (ярлык, перетаскивание на значок программы или ярлык, параметры запуска) не открывает второе окно: уже открытое выходит на передний план (свёрнутое — разворачивается), а переданные папка или файлы открываются в нём так же, как при перетаскивании в окно (п. 3.1): папка — с вопросом о несохранённых изменениях (п. 6.5), файлы добавляются в ленту. Пакетный режим (п. 10) работает отдельно, его это не касается.
  - **Последние папки на значке.** Правый щелчок по значку GeoPhotos в панели задач или в «Пуске» — список «Recent folders» (те же, что в «File → Open Recent», до 10). Щелчок открывает папку — в уже открытом окне или запуская программу. «Clear Recent» очищает и этот список.
  - **Направление съёмки.** Если в фото записано, куда смотрела камера (`GPSImgDirection`, пишут телефоны), у маркера текущего фото на карте — полупрозрачный сектор в эту сторону. Только у текущего фото, чтобы не загромождать карту; у фото без направления (фотоаппараты) — ничего. В тестовых фото автора направление есть только у снимков iPhone.
- **0.36.0 — Google Карты из меню фото, модель камеры в просмотре** (решение автора 2026-11-25, по предложению Claude; сделано — пп. 4.14, 4.19).
  - **«Open in Google Maps»** — пункт контекстного меню фото (п. 4.19), сразу после «Show on Map»; только у фото с координатами (у трека нет): браузер открывает Google Карты на точке фото — оттуда Street View и спутник. Координаты уходят в Google только по этому щелчку. На пустой карте меню нет (решение автора).
  - **Модель камеры в просмотре фото.** В подписи режима просмотра (пробел, п. 4.14) — модель камеры или телефона из файла: «iPhone 14 Pro Max», «Canon EOS 5D Mark II». Производитель не повторяется, если он уже есть в названии модели (не «Apple iPhone…», не «Canon Canon EOS…»). Нет модели в файле — строки нет. Выдержка, диафрагма, ISO, объектив — не показываются.
- **0.37.0 — Undo и Redo изменений координат, история поиска, избранные места и метка, цвета, размер ленты** (решения автора 2026-11-25…27; сделано — п. 6.6, пункт меню «Edit» — п. 4.9; история поиска, избранное, метка, Ctrl+F — п. 5.3; цвета — п. 4.8.1; размер ленты — п. 4.1).

### 9.4. Возможные планы

Идеи без сроков и без обязательства сделать: когда и будут ли — решается отдельно. Перед реализацией каждая обсуждается и переносится в п. 9.3.

- **Linux.** Сборка AppImage или `.deb` в облаке GitHub Actions; пути с `/`; exiftool из репозитория системы или кнопкой «Install for GeoPhotos» (архив `Image-ExifTool` на Perl). Видео — без миниатюр (заглушка, п. 3.3.5); «живые» фото на Linux не делаются: показываются как обычные. Нужен человек, который проверяет версии на Linux. Отложено до тех пор, пока у пользователя не будет WSL (Linux внутри Windows; окна Linux-программ видны на рабочем столе), — тогда Claude проверяет окно в WSL на главных сценариях, а тесты под Ubuntu уже идут в Actions (п. 9.3). Первый прогон в Actions (2026-11-25): unit-тесты под Ubuntu проходят; интеграционные — 6 падений, все из-за путей в духе Windows: вложенные имена собираются через `` (`asame.jpg` вместо `a/same.jpg`), добавленные файлы (`scanFiles`) не находятся, в т. ч. треки; имена файлов везде сравниваются без учёта регистра (на Linux `IMG.jpg` и `img.jpg` — разные файлы). Пока они не мешают (на Ubuntu интеграционные тесты не ставят отметку «ошибка»), чинятся в Linux-версии. До этого Linux-сборки не выпускаются: непроверенная хуже никакой; новый код без нужды не завязывается на Windows, а места, где без этого нельзя (как установка exiftool), выделены (решение пользователя, 2026-11-25).
- **macOS.** Сборка на Mac-машинах GitHub Actions; меню по правилам Mac (меню с именем программы, сочетания через Cmd); exiftool — архив `Image-ExifTool` или Homebrew; миниатюры видео — через Quick Look. Без подписи и нотаризации Apple (платно) macOS требует разрешать запуск вручную. Делать, только если появятся пользователи с Mac.
- **Android** — не нужен: телефон сам ставит координаты при съёмке; Electron на Android не работает.

## 10. Пакетный режим

Запуск без участия пользователя для записи адресов и высот:

```
GeoPhotos.exe --batch [параметры] <папка | файл ...>
```

- `--no-address` — не получать адрес (по умолчанию получать, п. 5.5);
- `--no-altitude` — не получать высоту (по умолчанию получать, п. 5.6);
- `--subfolders` — вместе с вложенными папками; без параметра вложенные папки не берутся и вопроса нет;
- `--overwrite` — перезаписывать адрес и высоту, которые уже есть; по умолчанию такие фото пропускаются.

Обрабатываются только фото и видео (с 0.22.0) с координатами. Главное окно не открывается; вместо него — маленькое окно хода: полоса, этап и «n of N» («Addresses: n of N»), оценка оставшегося времени, «Cancel»; ход виден и на значке в панели задач. Данные сразу записываются в файлы. По окончании — итог (записано, пропущено, ошибки); без ошибок окно закрывается само через 10 секунд, с ошибками ждёт закрытия. Подробности — в логе, итог — и в коде возврата.

Каждая точка запрашивается один раз (фото в одной точке получают одно и то же). Точки, по которым сервис не ответил, запрашиваются снова в конце — ещё два раза с паузой 10 с. «Cancel» во время запросов останавливает их, а уже полученное записывается; во время записи — останавливает запись. Закрытие окна во время работы — то же, что «Cancel». Фото без координат и фото, которым нечего добавить, — «skipped»; точка без ответа сервиса — ошибка этого фото. Код возврата: 0 — всё сделано, 1 — были ошибки, 2 — неверные параметры (сообщение с правилом запуска), 3 — отменено. Состояние главного окна (последняя папка, карта) пакетный режим не меняет.

Выход, пока адреса или высоты ещё получаются (пп. 5.5, 5.6): вопрос «Addresses and altitudes are still being received: n photo(s) left, about <time>» с кнопками «Stay»; «Save and finish in the background» — все изменения сохраняются, главное окно закрывается, оставшееся получает и записывает то же окно хода, что у пакетного режима, и закрывается само по окончании; «Exit without them» — дальше обычный вопрос о несохранённых изменениях (п. 6.5).
