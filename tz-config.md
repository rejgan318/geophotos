# ТЗ: конфигурация программы

Платформа: Electron + Node.js.

## 1. Формат

1.1. Все настройки хранятся в текстовых файлах формата JSONC.

1.2. Расширение файлов — `.json`.

## 2. Схемы

2.1. Для каждого файла конфигурации создаётся JSON Schema. Схема создаётся до кода и до самого конфига.

2.2. Схема описывает: поля, типы, обязательность, допустимые значения, значения по умолчанию, описание каждого поля.

2.3. Схемы лежат в папке `schemas` внутри программы и входят в сборку.

2.4. Каждый файл конфигурации содержит поле `"$schema"` со ссылкой на свою схему.

## 3. Расположение файлов

3.1. Настройки по умолчанию — папка `config` внутри программы.

3.2. Пользовательские настройки — папка `app.getPath('userData')`.

## 4. Чтение

4.1. Чтение — пакетом `jsonc-parser`. `JSON.parse` не использовать.

4.2. После чтения конфиг проверяется по схеме пакетом `ajv`.

4.3. При ошибке проверки программа выводит понятное сообщение: файл, поле, причина.

## 5. Запись

5.1. Запись — функциями `modify` и `applyEdits` пакета `jsonc-parser`. Комментарии в файле сохраняются.

5.2. `JSON.stringify` для записи конфигов не использовать.

## 6. Редактирование пользователем

6.1. Встроенных редакторов конфигурации в программе нет. Пользователь правит файлы любым текстовым редактором.

6.2. Подсказки и проверку при редактировании даёт редактор, который понимает поле `"$schema"` (например, VS Code): подсказки полей, описания, подсветка ошибок по схеме.

6.3. Пункт меню «Open Settings File» открывает пользовательский конфиг в программе, назначенной в Windows для `.json`. Если файла нет, он сначала создаётся: только поле `"$schema"` и комментарий о том, что в файл вносятся лишь изменённые поля, а значения по умолчанию и описания полей — в схеме.

6.4. Изменения применяются после перезапуска программы.

## 7. Пакеты

- `jsonc-parser`
- `ajv`

## Примечание

Названия пунктов меню в ТЗ указаны условно. Фактические названия берутся из файлов локализации (`tz.md`, п. 2.3).
